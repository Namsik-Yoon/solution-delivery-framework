# Retrospective Workflow

Adapt `templates/retrospective.md`. Compare intended KPIs with measured results and pending validation. Record failure cases, context/token waste, retries, manual rework and recurring code.

Propose evidence-backed framework changes for the next version; do not silently upgrade old projects. Split a runtime package only after repeated implementations justify it.
